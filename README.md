# MineSweeper Infinity

Бесконечный сапёр: поле не ограничено, мины расставляются процедурно из сида,
а открытые клетки сохраняются в файлы мира. Можно уйти, закрыть игру и вернуться
в тот же мир с тем же счётом, временем и положением камеры.

## Управление

| Действие | Кнопка |
|---|---|
| Открыть клетку | **Левая кнопка мыши** |
| Поставить флажок | **Правая кнопка мыши** (цикл: флажок → вопрос → пусто) |
| Помощник: открыть соседей цифры | **Двойной клик** по открытой цифре, если вокруг неё стоит ровно столько флажков, сколько она показывает |
| Двигать поле | **Зажать среднюю кнопку** и тянуть, или **двумя пальцами** на тачпаде |
| Приблизить / отдалить | **Колесо мыши**, на тачпаде — **щипок** или **Ctrl + прокрутка** (от 0.1× до 10×) |
| Окно параметров | **Esc** (открыть/закрыть) |
| Показать/скрыть строку состояния | **F3** |
| Новый мир с новым сидом | **Смайлик** в шапке |

В окне параметров (Esc) задаются сложность, сид и тема, там же список миров
с кнопками «Загрузить» и «Пересоздать мир».

Помощник открывает соседние закрытые клетки, когда флажки вокруг цифры расставлены
полностью — это привычный способ разгребать поле, не открывая клетки по одной.
Флажки при этом не снимаются, а если среди соседей окажется мина (флажок стоял
неверно), игра заканчивается — как в классическом сапёре.

## Туман

Открытые клетки освещают окрестность не сразу: вокруг них расходится туман, и
дальние закрытые клетки игрок не видит.

Дальность считается **квадратами** (расстояние Чебышёва) до ближайшей открытой
клетки, а не по кругу:

```
расстояние до открытой     стадия   как выглядит
1..4                       0        без тумана: чистый квадрат 9x9 вокруг клетки
5                          1        переход, 25 % цвета тумана
6                          2        переход, 50 %
7                          3        переход, 75 %
8 и дальше                 4        сплошной цвет тумана
```

Стадии 3 и 4 **некликабельны**: по ним нельзя ни открыть клетку, ни поставить
флажок. Пока в мире нет ни одной открытой клетки, туман закрыл бы всё поле и
кликнуть было бы некуда, поэтому центр экрана подсвечивается — вокруг него туман
отступает так же, как вокруг открытой клетки. Подсветка гаснет по первому клику.

Туман — только оформление: он нигде не хранится, ни в чанках, ни в сохранениях,
и целиком выводится из уже открытых клеток. Спрайты переходных клеток
смешиваются с цветом тумана один раз при смене темы, а клетки 4-й стадии просто
заливаются его цветом.

## Старт игры

Первый клик всегда приходится на безопасное место. Игра ищет ближайшую к точке
клика клетку, вокруг которой квадрат 3x3 свободен от мин (обход идёт квадратными
кольцами от курсора), и сдвигает поле так, чтобы эта клетка оказалась под
курсором. Сдвиг — на целое число клеток, поэтому подмена незаметна: закрытые
клетки выглядят одинаково, и выдать её может разве что строка состояния с
координатами. Так игра всегда начинается с открытой области, а не с подрыва.

## Сложность и очки

Сложность — уровень от **−4** до **5**, где 0 — базовая (около 9.8 % мин),
выше — плотнее, ниже нуля — разреженнее. Плотность растёт экспоненциально:

| Уровень | −4 | −2 | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|---|---|
| Мин | 4.0 % | 6.3 % | 9.8 % | 12.3 % | 15.3 % | 19.2 % | 24.0 % | 30.0 % |

Очки пропорциональны сложности: на уровне 0 и ниже они не начисляются вовсе,
на уровне 5 — множитель 2.5. За крупный разлёт даётся бонус, за подрыв на мину —
штраф. Сложность хранится в сохранении мира, поэтому у каждого мира она своя.

## Темы

Тема оформления — спрайтлист `sprites/<тема>.bmp` (сейчас `light` и `dark`).
В нём же лежит палитра интерфейса: **последняя строка** картинки, по одному пикселю
на роль. Слоты (подробнее в `theme.h`):

```
 0 фон окна и панелей              8  начало градиента заголовка
 1 фон кнопок                      9  конец градиента заголовка
 2 основной текст                 10  фон выделения (списки, поля)
 3, 7 свободно                    11  текст выделения
 4 светлая грань (бевел)          12  текст предупреждений
 5 тёмная грань (бевел)           13  приглушённый текст
 6 фон полей ввода и списков      14 цвет тумана, 15 свободно
```

Незаполненный слот помечен ярко-зелёным (`#10FF00` в светлой теме, `#0DCE00`
в тёмной) — тогда цвет подбирается автоматически. `light.bmp` — 4-битный,
при правке палитры важно сохранять формат файла.

## Файлы данных

На Windows всё лежит в `%APPDATA%\MineSweeper_Infinity`, на Linux — в
`~/.local/share/MineSweeper_Infinity`; набор файлов один и тот же:

- `settings.ini` — сложность, тема, последний мир, размер окна;
- `worlds/<дата_время>/world.ini` — сид, сложность, счёт, флажки, время, позиция камеры;
- `worlds/<дата_время>/regions/r<X>_<Y>.dat` — состояния клеток региона
  (три битовые карты на чанк: открытые, флажки и ACTIVE — клетки, ждущие открытия).

## Сборка

Qt 6 (Widgets), CMake. Код одинаков для Windows и Linux, соберётся любым
компилятором с C++17.

На Windows путь к папке проекта — только ASCII, иначе `moc` из MinGW не сможет
создать выходные файлы (на Linux это ограничение не действует).

```bash
cmake -S <путь_к_проекту> -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Проект удобно собирать через junction с ASCII-путём (например, `C:\u\MineSweeper_Infinity`).

### Сборка под Linux

Ubuntu / Debian — достаточно пакетов:

```bash
sudo apt install build-essential cmake ninja-build \
    qt6-base-dev qt6-l10n-tools qt6-tools-dev
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Замечания:

- ASCII-junction и все обходы путей из Windows-раздела не нужны;
- строка статуса и миры окажутся в `~/.local/share/MineSweeper_Infinity`;
- тачпад различается без эвристик: Linux отдаёт прокрутку тачпада с фазами
  жеста и пиксельной дельтой, поэтому панорамирование работает сразу;
- проверено на Ubuntu 24.04 (Qt 6.4.2, gcc 13): сборка, все 78 тестов стенда
  и тайминги кадров совпадают с Windows.

### Статическая сборка

Такой exe не требует DLL Qt рядом с собой. Обычная сборка (динамический Qt) остаётся
в корневом `CMakeLists.txt`, статическая описана отдельным проектом
`static/CMakeLists.txt`; исходный код у них общий. Сборка ведётся только
под Windows — на Linux проект `static/` сразу скажет об этом и отошлёт
к обычной сборке.

```bash
scripts/build-static.sh --build-qt   # один раз: собрать статический Qt и приложение
scripts/build-static.sh              # дальше — только приложение
```

Скрипт скачивает и собирает `qtbase` из исходников, ставит его в
`C:/Qt/<версия>/mingw_64_static`, собирает приложение и проверяет через `objdump`,
что в exe не осталось зависимостей от `Qt6*.dll` и рантайма MinGW.

Чем проект `static/` отличается от основного:

- нет `LinguistTools` — статический Qt собирается из одного `qtbase`, поэтому
  переводы не компилируются;
- платформенный плагин и плагин стиля подключаются к exe явно
  (`QWindowsIntegrationPlugin`, `QModernWindowsStylePlugin`): без первого окно
  не создастся, без второго вместо системного вида будет Fusion;
- рантайм MinGW линкуется статически (`-static`), иначе рядом с exe всё равно нужны
  `libstdc++-6.dll`, `libgcc_s_seh-1.dll` и `libwinpthread-1.dll`.

При добавлении новых файлов их нужно вписывать в оба `CMakeLists.txt`.

## Устройство

| Файл | Назначение |
|---|---|
| `worldmanager.*` | чанки в кэше, процедурные мины, состояние клеток |
| `solver.*` | открытие клеток разлётом: стек обхода, прерывание по запросу |
| `loader.*` / `saver.*` / `region.*` | фоновая подгрузка и сохранение регионов |
| `minefieldwidget.*` | отрисовка, мышь, масштаб, предзагрузка чанков за экраном |
| `fogofwar.*` | туман: расстояния до открытых клеток и спрайты перехода |
| `mainwindow.*` | окно, счётчики, мир и его сохранение |
| `settingspanel.*` + `.ui` | окно параметров |
| `theme.*` | палитра интерфейса из спрайтлиста |
| `scoring.*` | формула очков |
| `settings.*` / `world.*` | настройки и метаданные мира |
